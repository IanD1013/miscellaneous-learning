只有当循环条件所读取的内容发生改变，直到测试条件为假（失败）时，循环才会结束。
对于任何正数，翻倍操作都可以做到这一点：

```cpp
int value = 3;
int passes = 0;
while (value < 20) {
    value *= 2;
    ++passes;
}
```

`value` 依次变为 6、12、24，而 `24 < 20` 不成立，因此 `passes` 最终为 3。
如果将 `value` 设为 0，则什么都不会改变：0 翻倍后仍是 0，`0 < 20` 永远不会为假，循环将无法终止。
负数起始值不能进入循环的原因则不同：每次翻倍都会使其进一步小于零，一旦超出第 2.2 课中提到的 `int` 范围下限，其算术运算就会导致未定义行为，而不是一个值得预测的数值。

### 当运行结果为空时

编译器在这里不会报错，因为语法完全正确，只是算术运算无法取得进展。
这样的循环会一直运行，直到达到运行时间限制：当前运行环境给整个运行分配了 20 秒，超时后便会终止，因此返回的结果中根本没有任何内容，而不是返回一个错误的数字。
编译最多只需要大约一秒钟，因此如果在这之后程序依然长时间没有响应，那就是循环的问题，而不是构建过程的问题。
再次提交相同的代码同样会消耗那 20 秒；修复的方法在于修改循环条件，或者在循环开始前添加检查。

### 修复初始代码

`countDoublings(int start, int target)` 返回 `start` 达到 `target` 所需的翻倍次数，当它已经大于或等于 `target` 时返回 0。
初始代码中的 `while` 条件为 `value > 0 && value < target`。
这个额外的测试条件确实可以在起始值为 0 或负数时结束循环，但函数随后会报告 0 次翻倍，而 0 已经是起始值一开始就足够大时的正确答案了。
根据文档要求，起始值为 0 或负数时应返回 -1。

将该测试从条件中移除，并作为守卫条件（guard）放在循环之前：当 `start` 为 0 或负数时，在进行任何翻倍前直接返回 -1，只保留一个单纯比较 `value` 和 `target` 的条件。
如果去掉了 `value > 0` 却没有添加守卫条件，程序将在起始值为 0 时挂起。
在每次翻倍发生后再进行计数，因此 `countDoublings(8, 8)` 和 `countDoublings(50, 10)` 都为 0，`countDoublings(3, 20)` 为 3，`countDoublings(1, 1000000000)` 为 30（这是这些输入允许的最长增长过程：`start` 不会超过 1000000，`target` 不会超过 1000000000，这保证了每次翻倍的值都在 `int` 能容纳的范围内）。
每个测试用例都必须能执行到它自己的 return 语句，因为只要有一个无法返回，就会导致整个运行超时。

### 解答

```cpp
struct Solution {
    static int countDoublings(int start, int target) {
        // 无法增长的起始值永远到不了目标，此时答案为 -1
        if (start <= 0) {
            return -1;
        }
        int value = start;
        int doublings = 0;
        while (value < target) {
            value *= 2;
            ++doublings;
        }
        return doublings;
    }
};
```
