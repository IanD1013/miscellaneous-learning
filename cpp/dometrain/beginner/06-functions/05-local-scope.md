花括号开启一个代码块，而在其中声明的名称属于该代码块。
它从声明处开始可见，直到匹配的 `}` 为止，在块外部则是未知的。
这个可见范围就是该名称的局部作用域，这样的变量被称为局部变量。

```cpp
int score = 10;
{
    int score = 0;
    score += 5;
}
// 外层的 score 仍然保存 10
```

内部的 `int score` 并不会复用外部变量。
声明语句总是会创建一个新变量，因此这里存在两个变量，且内部变量遮蔽了外部变量：在该代码块内部，该名称代表内部变量，并完全隐藏了外部名称。
`score += 5` 将其从 0 变为 5，而外部变量保持为 10 未受影响。
在闭合花括号处，内部变量离开作用域，生命周期结束，`score` 重新指代外部变量。

这里没有任何错误，警告在此处也不会导致运行失败，因此变量遮蔽往往表现为一个错误的数值。

在循环体花括号之间声明的变量会在每次迭代中重新创建，并在迭代结束时销毁，因此它不会保留任何状态。
需要持续保留的计数器必须在循环开始之前声明。

### 赋值操作影响的是哪个计数器

`countMultiples(int limit, int factor)` 以 `int` 形式返回从 1 到 `limit`（包含 `limit`）之间能被 `factor` 整除的数值个数。
初始代码可以编译，但在本应计数的地方都返回 0：循环体内的 `if` 内部存在第二个 `int count = 0;`，因此 `count += 1` 增加的是一个在下一行就会销毁的变量，而循环上方的 `count`（即 `return count;` 所读取的变量）从未改变。

移除该内部声明就是全部的修复工作。
保护条件 `if (factor <= 0)` 会在因子小于等于 0 时返回 -1，这是一种计数本身永远不会产生的拒绝标识，同时也能避免 `%` 的右操作数为 0（C++ 将此操作定义为未定义行为，此处的测试用例均不会触发该情况）。
保持 `for` 循环及其从 1 开始的初始值：如果从 0 开始，当因子为 1 时计数值会多 1。
运行器定义了该程序唯一的 `main`，因此你的文件中无需声明 `main`。
`limit` 范围为 0 到 1000，`factor` 范围为 -10 到 1000。
`countMultiples(10, 3)` 结果为 3，`countMultiples(10, 1)` 结果为 10，而当 `limit` 为 0 或 `factor` 大于 `limit` 时均返回 0，`countMultiples(10, -3)` 返回 -1。

### 解答

```cpp
struct Solution {
    static int countMultiples(int limit, int factor) {
        if (factor <= 0) {
            return -1;
        }
        int count = 0;
        for (int value = 1; value <= limit; value += 1) {
            if (value % factor == 0) {
                // 累加的是循环上方声明、最后被返回的 count
                count += 1;
            }
        }
        return count;
    }
};
```
