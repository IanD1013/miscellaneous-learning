头像上传功能允许任何已登录用户上传最大 5 MB 的文件，并向所有打开该个人资料的人展示，这使其成为应用程序攻击面上最大的输入点。
发送者决定了其中的全部内容：字节内容、文件名以及请求声明的 `Content-Type`。
名为 `me.jpg` 的文件可能是一个包含脚本的 HTML 页面，因此仅检查文件扩展名只检验了发送者输入的内容。
本设计将每个新文件都视为具有敌意的，直到扫描器对其完成检查为止，并以即使是恶意文件也无法作为应用程序一部分运行的方式来提供文件。

### 存储新文件

浏览器（Client / User 模块）通过 API 网关将图片发送到个人资料服务（Service），该服务会拒绝任何超过 5 MB 的内容。
该服务会忽略用户的文件名：`../../config/app.json` 会导致路径遍历（path traversal），而两个用户同时上传 `photo.png` 则会发生相互覆盖。
它会为每个文件分配一个**生成的名称**，将文件存入对象存储，并在个人资料数据库（Database (SQL)）中记录哪个个人资料拥有该名称。
服务自身的磁盘上不保存任何内容。
Web 根目录（Web 服务器从中提供页面的文件夹）会是最糟糕的存放地点：其中的每个文件都会获得应用程序自身域名下的 URL。

随后，新文件会处于**隔离区（quarantine）**状态：已存储，但在扫描器批准之前不会提供给任何人。
对已经显示在个人资料中的图片进行扫描，对于在此期间加载过它的所有人来说都为时已晚。
该服务将包含生成名称的扫描作业放入消息队列中，并不经等待直接回复浏览器。
文件扫描器（Worker / Background Job）获取该作业，从对象存储中读取文件，根据其字节内容确认其确实是 PNG 或 JPEG，检查是否存在恶意软件，并在存储中为该文件打上裁定结果的标签。
当扫描器繁忙或停机时，队列会保留作业，这也是它是从服务到扫描器的唯一路径的原因。
就像 URL 抓取器一样，扫描器处理的是陌生人选择的输入，因此它在专用网络（private network）之外运行。
它通过存储中的标签报告其裁定结果，绝不连接到个人资料服务或数据库。
控制了扫描器的文件可以在那里运行自己的代码，但该代码仍然在专用网络之外，因此它无法比任何陌生人更接近服务或个人资料记录。

### 提供已批准的文件

如果从应用程序自身的域名提供服务，经过伪装的 HTML 文件就是存储型 XSS：无论谁打开其 URL，都会在应用程序的源（origin）下以其已登录的会话运行该脚本。
因此，图片来自一个**独立的域名**，即其自身的站点（应用程序的子域名仍然属于同一站点）。
那里的脚本运行在一个不包含任何会话 Cookie 的源中，且同源策略会阻止其读取应用程序的页面。
浏览器从 CDN（内容分发网络）加载图片，即该域名上的缓存服务器，它们在有人首次请求某个文件时从对象存储中获取该文件。
存储只允许 CDN 读取标记为已批准的文件，从而使隔离区中的文件远离所有人。

最小权限原则确保浏览器完全没有存储访问权限：它绝不连接到对象存储，甚至不能连接存储进行上传，因为那样会绕过服务及其 5 MB 的限制。
出于同样的原因，网关也没有存储访问权限；它将每次上传传递给个人资料服务。
CDN 也不会连接到个人资料服务或数据库。
服务和数据库运行在专用网络中，所有从外部到达它们的请求都通过网关传入。

### 在图板上

将个人资料服务和个人资料数据库放置在 Private Network 区域内，将扫描器放置在该区域外。
对象存储、CDN 和队列也保持在外部：浏览器连接到 CDN，CDN 和扫描器连接到存储，扫描器连接到队列以获取每个作业，因此这三者中的任何一个位于区域内都会成为跨越其信任边界且绕过网关的途径。
在浏览器和区域之间的模块中，只有网关可以放在任一侧。
按照调用或作业传递的方向绘制每个连接；扫描作业的箭头从队列指向扫描器，尽管是扫描器打开了该连接。
浏览器最终将恰好拥有两个连接，一个连接到网关，一个连接到 CDN。
