SSH 密钥登录将一对密钥分置于两台机器上。
**私钥**保留在发起连接的机器上。
**公钥**则放入被登录账户家目录下的 `~/.ssh/authorized_keys` 中，每行一个公钥。
登录时，SSH 客户端使用私钥对来自连接的数据进行签名，而 SSH 服务端 sshd 则使用该文件中的公钥来验证该签名。
服务端永远不需要私钥，因此私钥绝不应传到那里。
公钥仅用于验证签名，因此它并不是机密。

一个自动化部署作业将以 `deploy` 用户的身份登录此机器，该账户没有可用的密码。
它的家目录 `/home/deploy` 的权限为 deploy:deploy 且权限模式为 755，目前尚未创建 `.ssh` 文件夹。
你的账户代表该作业，因此密钥对存放在你自己的 `~/.ssh` 中，而该目录目前也尚未创建。

### 使用 ssh-keygen 创建密钥对

`ssh-keygen` 会将密钥对写入两个文件：私钥，以及旁边添加了 `.pub` 后缀的公钥。
为你自己登录构建服务器所用的密钥可以这样生成：

```bash
ssh-keygen -t ed25519 -f ~/.ssh/buildbox_ed25519 -C learner@laptop
```

- `-t ed25519` 选择密钥类型。如果不指定 `-t`，此机器上的 ssh-keygen 会生成 RSA 密钥，这种密钥更长且生成速度慢得多。
- `-f` 指定私钥文件的名称。当路径位于 `~/.ssh` 内部且该文件夹尚不存在时，ssh-keygen 会以 700 权限模式创建它，以便只有你能访问；它不会创建其他文件夹。你自己使用 `mkdir` 创建的 `~/.ssh` 初始权限模式为 755，而 ssh-keygen 不会修改已存在文件夹的权限模式，因此需要对其运行 `chmod 700`。
- `-C` 设置注释（comment），这是公钥行末尾的标签，用于在 authorized\_keys 文件中区分不同的密钥。如果不指定，则会使用你的用户名和主机名。
- 如果不加 `-N`，ssh-keygen 会提示输入密码短语（passphrase）并用它加密私钥文件，这样私钥即便被窃取也无法单独使用；供人工使用的密钥应当设置密码短语。`-N ''`（两个单引号之间没有任何内容）则在命令行直接指定空密码短语。部署作业没有人工来输入密码短语，因此其密钥不需要密码短语，单凭该文件即可完成登录：它只应当存放在 CI 系统的机密设置（secret settings）中，不能放在其他任何地方。

ssh-keygen 创建的私钥权限模式为 600，`.pub` 文件的权限模式为 644。
请保持私钥为 600，如果其模式被更改，可以用 `chmod 600` 将其还原：如果私钥的组或其他用户权限位不是 0，SSH 客户端将拒绝使用该私钥。
`.pub` 文件只有一行，包含类型、密钥和注释，例如 `ssh-ed25519 AAAAC3NzaC1lZDI1NTE5AAAAI... learner@laptop`。

### sshd 接受的所有者和权限模式

任何能够写入 deploy 的 authorized\_keys 的账户，都可以添加自己的公钥并以 deploy 身份登录。
因此，如果该账户的家目录、其 `.ssh` 文件夹或 `authorized_keys` 可被其他账户写入，sshd 将拒绝密钥登录。
此外，sshd 是以 deploy 身份打开 authorized\_keys 的，因此 deploy 无法读取的文件（例如所有者为 root 且权限模式为 600 的文件）也会导致登录失败。
文件所有者或模式不正确的有效密钥，遭遇的拒绝情况与错误的密钥完全相同。

你的账户可以读取 `/home/deploy` 但无法写入，因此在 deploy 侧需要使用 `sudo`。
`install -d` 可以在同一条命令中创建目录并设置其所有者、所属组和权限模式，就像 `install` 对文件所做的那样：

```bash
sudo install -d -m 750 -o root -g www-data /srv/site
```

要复制 `.pub` 文件，请使用带有相同三个选项的 `install`，就像你之前为 reports 服务的 SMTP 密码所做的那样，只是将 `/dev/stdin` 替换为该文件。
`install` 会替换目标位置已存在的任何文件，这非常适合尚无任何密钥的账户。
对于已有密钥的账户，你应当改为追加行（使用 `tee -a`，通过 `sudo -u` 以该账户身份运行），以确保其原有的其他密钥继续有效。

### 为 deploy 安装密钥

- 以你自己的身份，创建密钥对 `~/.ssh/deploy_ed25519` 和 `~/.ssh/deploy_ed25519.pub`：类型为 ed25519，注释严格为 `deploy@ci`，无密码短语。
- 创建 `/home/deploy/.ssh`，所有者为 deploy，所属组为 deploy，权限模式为 700。
- 将刚刚生成的 `.pub` 文件安装为 `/home/deploy/.ssh/authorized_keys`，所有者为 deploy，所属组为 deploy，权限模式为 600。私钥的任何副本均不得以任何名称存放在 `/home/deploy` 中的任何位置。
- 保持 `/home/deploy` 的初始状态不变，既不要放宽权限以便跳过 `sudo`，也不要收紧权限。
