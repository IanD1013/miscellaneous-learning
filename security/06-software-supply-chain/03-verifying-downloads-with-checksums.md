在运行下载的脚本之前，你需要确认它包含的字节与项目发布时的内容完全一致。
**校验和（checksum）**，即文件字节的哈希值，可以告诉你这一点：项目会为每次发布的每个文件公布一个校验和，如果一个副本计算出的哈希值相同，则它包含相同的字节。
仅仅运行脚本看它是否能工作说明不了任何问题：发布后被篡改的脚本通常也能无报错运行，执行真实脚本所做的一切，外加添加进去的任何恶意内容。
OWASP 将在没有此类校验的情况下使用代码归类在 A08:2025 软件和数据完整性故障（Software or Data Integrity Failures）之下。

这里使用的哈希函数是 SHA-256。
相同的字节总是产生相同的 64 个字符的十六进制摘要，而修改任意一个字节都会产生完全不同的摘要。
SHA-256 用于存储密码可能速度太快了，但对于下载校验来说这无关紧要：因为这里没有需要猜测的秘密，只有一个需要比较的文件。

### sha256sum 和校验和列表

`sha256sum` 会输出你指定的每个文件的校验和，后跟两个空格和文件名。
如果保存到文件中，该输出就是一个校验和列表，也就是项目通常以 `SHA256SUMS` 形式发布的格式。
`sha256sum -c` 会读取列表，再次对其中命名的每个文件进行哈希计算，并为每个文件输出 `OK` 或 `FAILED`。
以下是它在 `/tmp` 中的两个小文件上的运行示例：

```text
$ cd /tmp
$ printf 'one\n' > a.txt; printf 'two\n' > b.txt
$ sha256sum a.txt b.txt > demo.sha256
$ cat demo.sha256
2c8b08da5ce60398e1f19af0e5dccc744df274b826abe585eaba68c525434806  a.txt
27dd8ed44a83ff94d557f9fd0412ed5a8cbca69ea04922d88c01184a07300a5a  b.txt
$ printf 'Two\n' > b.txt
$ sha256sum -c demo.sha256
a.txt: OK
b.txt: FAILED
sha256sum: WARNING: 1 computed checksum did NOT match
```

仅将一个字母改为大写就足以让 `b.txt` 校验失败。

一个通过校验的文件只能证明它与列表匹配，仅此而已。
下载通常来自**镜像站（mirror）**，即托管项目文件副本的服务器，任何能够篡改那里文件的人也可以篡改保存在旁边的校验列表。
只有当列表来自攻击者无法与文件一同编辑的地方（例如项目自己的发布页面）时，列表才能保护你的安全。
出于同样的原因，切勿像演示中构建 `demo.sha256` 那样根据下载的文件重新生成发布的列表：因为该列表描述的是磁盘上现有的内容，无论是否被篡改过。

### 安装通过校验的发布版本

你的 shell 起始于 `/home/learner/downloads`。
其中包含从镜像站下载的部署脚本的两个发布版本：`deploy-helper-2.1.0.sh` 和 `deploy-helper-2.1.1.sh`，以及从项目发布页面复制的 `SHA256SUMS`。
这两个脚本中有一个在镜像站发布后被更改过了。

- 对照 `SHA256SUMS` 校验这两个脚本，并保持 `SHA256SUMS` 原样不动。
- 使用 `rm` 删除校验失败的脚本，无论其版本号是多少。不要对其重命名、移动或编辑；如果以后需要该版本，应重新下载并重新校验。
- 以你自己的身份创建 `~/bin`，不要使用 `sudo`。它最终应该归你所有，权限模式为 755，或者为 750 或 700 以防止其他账户访问。
- 将通过校验的脚本（完全保持下载原样）复制到 `~/bin/deploy-helper`，权限模式设为 755（700 也可以）。`install -m 755` 可以在一条命令中完成复制并设置其权限模式，而且不使用 `sudo` 时副本归你所有。它必须是一个副本，而不是指向下载文件的符号链接。

`~/bin` 的所有者和权限模式至关重要，因为如果该目录存在，Debian 的 `~/.profile` 会在登录时将 `~/bin` 放在 `PATH` 的最前面。
之后你输入的命令名称会先在那里查找，然后再去 `/usr/bin` 查找，因此能够写入 `~/bin` 的账户可以在你完成校验后替换 `deploy-helper`，或者添加其恶意的 `ls`。
使用 `sudo mkdir` 创建的 `~/bin` 属于 root：你自己的安装操作会因为 Permission denied 而失败，而通过运行 `chmod 777` 来解决该问题则会让每个账户都可以向其中写入。

此 shell 是在 `~/bin` 存在之前启动的，因此直到下次登录前 `deploy-helper` 不会被识别为命令，你也不需要运行它。
完成后，`ls -ld ~/bin ~/bin/deploy-helper` 会显示两者的所有者和权限模式。
