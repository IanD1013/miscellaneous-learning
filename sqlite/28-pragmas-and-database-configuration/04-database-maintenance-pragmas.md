### 使用 SQLite PRAGMA 进行数据库维护

生产环境中的数据库会随着时间推移产生损耗 - 删除的行会在数据文件中留下碎片空隙，索引会变得碎片化，查询规划器的统计信息也会过时。
SQLite 提供了几个维护命令来保持数据库的健康与高效。
对于任何在生产环境中管理 SQLite 数据库的开发者来说，理解这些工具都是必不可少的。

### 数据库维护的工作原理

SQLite 将数据存储在单个文件的页（page）中。
当删除或更新行时，页面可能会变成部分为空或产生碎片。
随着时间的推移，这会浪费磁盘空间并拖慢查询速度。
SQLite 还会维护内部统计信息，以帮助查询规划器选择高效的执行策略。
三个关键的维护工具可以解决这些问题：

1. **完整性检查（Integrity checking）** - 遍历每一个页、索引和表，以验证内部结构是否一致且未损坏
2. **清理碎片/压缩（Vacuuming）** - 重建数据库文件，回收未使用的页，并将数据整理碎片化为连续的页
3. **优化统计信息（Optimizing statistics）** - 更新查询规划器用于选择高效查询计划的内部统计信息

### 语法

```sql
-- 验证数据库结构完整性
PRAGMA integrity_check;
-- 如果数据库健康，返回 'ok'
-- 如果发现损坏，返回错误描述

-- 你也可以限制报告的错误数量
PRAGMA integrity_check(100);

-- 重建数据库文件以回收空间
VACUUM;

-- 更新查询规划器的统计信息
PRAGMA optimize;
```

### 示例

```sql
-- 检查整个数据库的完整性
-- 健康的数据库返回单行：'ok'
PRAGMA integrity_check;
-- 结果：ok

-- 经过大量 DELETE 操作后，文件中可能存在未使用的页。
-- VACUUM 会以紧凑的方式重写文件：
VACUUM;

-- 在插入或删除大量数据之后，
-- 刷新查询规划器的统计信息：
PRAGMA optimize;
```

### 理解完整性检查结果

`integrity_check` PRAGMA 会执行全面检查：

- 验证每个表和索引的 B-tree 结构
- 检查索引条目是否与对应的表行匹配
- 验证页级校验和以及空闲列表（free-list）的完整性
- 确认外键引用在结构上完好无损

当数据库健康时，结果是包含文本 `ok` 的单行记录。
如果检测到损坏，每个问题都会作为单独的一行报告，并附带描述性错误消息。

### 何时使用各个命令

| 命令 | 何时使用 | 性能影响 |
| --- | --- | --- |
| `PRAGMA integrity_check` | 崩溃后、备份后或进行定期健康检查时 | 读取整个数据库 - 在大型数据库上较慢 |
| `VACUUM` | 批量删除后，或者当文件大小远大于实际数据量时 | 重写整个文件 - 临时需要 2 倍的磁盘空间 |
| `PRAGMA optimize` | 数据发生重大变动后，或者在执行复杂查询之前 | 快速 - 仅分析需要分析的表 |

### 你的任务

你有一个包含员工和部门数据的多表数据库。
已经插入了一些记录，并且数据库正在使用中。
你的任务是运行相应的维护命令来**验证数据库完整性是否完好**。

编写一条 SQL 语句来检查数据库的结构健康状况并返回完整性状态。
健康的数据库应该返回包含 `ok` 的结果。

### 解答

```sql
-- 检查数据库的结构完整性，健康的数据库返回一行 'ok'（列名为 integrity_check）
PRAGMA integrity_check;
```
