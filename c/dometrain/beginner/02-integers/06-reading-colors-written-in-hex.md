### 保留源记法

一个遗留主题将红色记录为 `0xC8`，绿色记录为 `0x64`，蓝色记录为 `0x32`，alpha 记录为 `0377`。
`intensity_score` 转录这些字面量，并接收 0 到 1000000 范围内的 `scale`。

没有前缀的整数字面量是十进制。
`0x` 前缀表示十六进制，前导零表示八进制。
每个前缀选择一种数制基数并改变编译器解释数字的方式，而不是改变存储的 `int` 类型。
这三种颜色值的总和为 350。

在声明的数值范围内，将该总和乘以 scale 最多达到 350000000。
加上 alpha 后会产生不大于 350000255 的可表示结果。
请使用通道各自确切的源码形式进行声明，将总和乘以 `scale`，然后加上 alpha。
请保持所有四个字面量清晰可见，而不是替换为它们所代表的值。
Token 检查要求使用原始拼写形式 `0xC8`、`0x64`、`0x32` 和 `0377`；它们会拒绝十进制形式 200、100、50 和 255，以及预先计算出的通道总和 350。
进制属于源码记法，因此返回的数值本身无法区分这两种拼写，这就是检查机制会直接读取你代码的原因。

普通的小比例、零以及一百万的边界值都使用相同的表达式。
请注意，`0x64` 是十进制的 100，而不是十进制的 64，而八进制的 `0377` 是十进制的 255。

### 解答

```c
int intensity_score(int scale)
{
    // 主题文件以十六进制记录红、绿、蓝，以八进制记录 alpha
    int red = 0xC8;
    int green = 0x64;
    int blue = 0x32;
    int alpha = 0377;
    return (red + green + blue) * scale + alpha;
}
```
