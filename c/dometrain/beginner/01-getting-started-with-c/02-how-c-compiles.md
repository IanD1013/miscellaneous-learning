一次构建可能包含多个 `.c` 文件和多个共享头文件，但这两个数量并不会产生相同数量的目标文件。

预处理器在编译前处理诸如 `#include` 之类的指令。
它将所请求的头文件文本展开到源文件中。
展开后的源代码就是一个翻译单元（translation unit），编译器将每个翻译单元转换为一个目标文件。
头文件本身不会生成目标文件。
编译完成后，链接器会将这些目标文件合并到程序中。
因此，对于本练习而言，无论头文件的数量是多少，一个 `.c` 文件就意味着一个目标文件。

函数签名还引入了带类型的输入。
在括号内，`int c_files` 是一个参数声明：`int` 是类型，`c_files` 是其在函数内部的局部名称。
逗号 `,` 将其与 `int h_files` 分隔开。
这是一个逗号分隔的参数列表。
当评分程序发起调用时，每个实参都会按从左到右的位置进行绑定：第一个数字赋给 `c_files`，第二个数字赋给 `h_files`。

实现 `object_file_count`，使其返回的 `int` 为 `.c` 文件的数量。
在计算中忽略 `h_files`。
输入为 4 和 9 时，返回 4；输入为 0 和 3 时，返回 0，因为单独的头文件不会生成任何目标文件。
评分程序检查的是返回值，而不是控制台输出。

### 解答

```c
// 每个 .c 文件生成一个目标文件，头文件不生成目标文件
int object_file_count(int c_files, int h_files) {
    return c_files;
}
```
